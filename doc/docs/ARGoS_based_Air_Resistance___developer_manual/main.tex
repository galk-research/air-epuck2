\section{ARGoS Engines Used by This Project}
ARGoS is modular: a configuration file selects which \emph{plugins} are used for physics, robot models, visualization, and media.

\subsection{Physics engine: \texttt{dynamics2d} (Chipmunk)}
This project integrates at the \textbf{dynamics2d} physics level. In ARGoS~3, \texttt{dynamics2d} is a 2D physics-engine plugin
whose rigid-body backend is \textbf{Chipmunk}. The wind/drive forces are applied as \textbf{Chipmunk impulses} to the underlying
\texttt{cpBody} after each physics tick.

In the experiment XML, the physics engine is selected explicitly:
\begin{lstlisting}[language=XML]
<physics_engines>
  <dynamics2d id="dyn2d"/>
</physics_engines>
\end{lstlisting}

\paragraph{Why “Chipmunk callbacks” appear in this codebase.}
Chipmunk provides a \emph{post-step callback} mechanism to safely apply impulses after collision resolution. ARGoS dynamics2d exposes
Chipmunk bodies internally; this project schedules one post-step callback per tick to apply the accumulated impulse vector
(see Sec.~\ref{sec:impulse-pipeline}).

\paragraph{What if a different physics engine is used?}
If the experiment selects a different physics engine (e.g., \texttt{dynamics3d}), there is no Chipmunk \texttt{cpBody}.
Therefore, this project’s impulse integration is designed for \textbf{dynamics2d}. Experiments must include \texttt{dynamics2d}
for the wind/impulse behavior to take effect.

\subsection{Robot model plugins (e-puck2, foot-bot, others)}
The controller itself is \textbf{robot-agnostic} at the ARGoS interface level (generic sensors/actuators, see Sec.~\ref{sec:robot-agnostic}),
but the experiment chooses specific robot model plugins:

\section{Architecture}
\subsection{Robot-agnostic controller design}
\label{sec:robot-agnostic}
The base controller \codeid{CAirResistance} uses only \textbf{generic} ARGoS interfaces:
\begin{itemize}
  \item \codeid{CCI\_DifferentialSteeringActuator}
  \item \codeid{CCI\_PositioningSensor}
  \item \codeid{CCI\_RangeAndBearingSensor} / \codeid{Actuator}
\end{itemize}
No e-puck2-specific CCI interfaces are required by the core implementation. Robot specificity belongs in \textbf{experiment XML}
(robot type tags, robot plugins to load), and in optional \textbf{example controllers}.

\subsection{Core Controller: \texttt{CAirResistance}}
\paragraph{Lifecycle and Extensibility.}
\codeid{CAirResistance} derives from \codeid{CCI\_Controller}. Lifecycle methods and key helpers are \textbf{virtual} and designed
for subclassing.

\paragraph{Important protected hooks (what they do).}
\begin{itemize}[itemsep=4pt]
  \item \textbf{\codeid{EnsurePhysicsHandle()}} — Cache the Chipmunk body pointer and derive the robot's effective radius (meters)
  from the AABB. Safe to call every tick.
  \item \textbf{\codeid{GetYawRadians()}} — Return yaw \(\psi\) (world frame) from the positioning sensor; used for the forward unit vector \(\unitvect{f}(\psi)\).
  \item \textbf{\codeid{HandleAerodynamicsPreStep()}} — Reset \(\vect{J}_{\mathrm{sum}}\); add wind impulse using \(\vect{w}_{\mathrm{eff}}\); broadcast radius (RAB byte 0).
  \item \textbf{\codeid{HandleAerodynamicsPostStep()}} — Register a Chipmunk post-step callback to apply \(\vect{J}_{\mathrm{sum}}\) after collisions.
  \item \textbf{\codeid{ComputeEffectiveWind()}} — Compute \(\vect{w}_{\mathrm{eff}}=(1-r)\vect{w}\) where \(r\) is the wake reduction from neighbors.
  \item \textbf{\codeid{IsBlockedByRAB(Real\& r)}} — From RAB neighbors, compute \(r\in[0,1]\) via geometric overlap of wakes (Sec.~\ref{sec:wake-blocking}).
  \item \textbf{\codeid{DriveImpulse(Real v\_cm\_s)}} — Add forward impulse \(\tfrac{m}{100}v\,\unitvect{f}(\psi)\) (cm/s \(\rightarrow\) m/s factor \(1/100\)).
  \item \textbf{\codeid{ApplyWindImpulse()}} — Add \(\tfrac{m}{100}\,\vect{w}_{\mathrm{eff}}\) to the per-tick accumulator.
\end{itemize}

\paragraph{Impulse Pipeline (per tick).}
\label{sec:impulse-pipeline}
\begin{enumerate}[itemsep=2pt]
  \item \textbf{Pre-step}: Reset the impulse accumulator; compute and add the wind impulse (possibly reduced by blocking); broadcast radius via RAB.
  \item \textbf{Drive}: Add a forward drive impulse along current yaw using the desired base speed.
  \item \textbf{Post-step}: Schedule a single Chipmunk \emph{post-step} callback to apply the summed impulse after collisions.
\end{enumerate}

\paragraph{AABB (Axis-Aligned Bounding Box).}
An \textbf{AABB} is the smallest rectangle (in world axes) that contains the robot body: it has min/max corners \((x_{\min},y_{\min})\)
and \((x_{\max},y_{\max})\). We derive an effective radius \(R\) from its width/height:
\[
R \approx \tfrac{1}{2}\max(x_{\max}-x_{\min},\,y_{\max}-y_{\min}).
\]
This gives a robust, robot-model-independent scale for wake geometry.

\section{Physics Integration Details}
This project integrates with ARGoS dynamics2d object models:
\begin{itemize}
  \item \textbf{Single-body robots} (e.g., e-puck2) expose a single Chipmunk \codeid{cpBody}.
  \item \textbf{Multi-body robots} (e.g., foot-bot) expose multiple Chipmunk bodies; body index 0 is treated as the chassis.
\end{itemize}
The controller caches the \codeid{cpBody*} and uses it to apply impulses post-step at the center of mass (COM).

\section{Algorithmic Details (with Equations)}
\subsection{Impulse Model (definition of \texorpdfstring{\(\vect{w}_{\mathrm{eff}}\)}{weff} + numeric example)}
Per tick we accumulate world-frame impulses:
\begin{align}
  \vect{J}_\text{wind}  &= \frac{m}{100}\,\underbrace{\vect{w}_\text{eff}}_{\text{effective wind in \si{cm/s}}},\\
  \vect{J}_\text{drive} &= \frac{m}{100}\,v_d\,\unitvect{f}(\psi),\\
  \vect{J}_\text{sum}   &= \vect{J}_\text{wind} + \vect{J}_\text{drive}.
\end{align}
\textbf{Definition.} Let \(\vect{w}\) be the global wind and \(r\in[0,1]\) the reduction due to upwind neighbors. The effective wind is
\[
  \boxed{\ \vect{w}_\text{eff} = (1-r)\,\vect{w}\ } \quad \text{(with \(r\) computed in Sec.~\ref{sec:wake-blocking}).}
\]
Here \(m\) is body mass (Chipmunk), \(v_d\) the desired forward speed (\si{cm/s}), and \(\unitvect{f}(\psi)\) the unit forward vector given yaw \(\psi\).
A single post-step callback applies \(\vect{J}_\text{sum}\) at the COM after collisions.

\paragraph{Numeric example (with picture).}
Let \(m=\SI{0.08}{kg}\), \(v_d=\SI{10}{cm/s}\), and \(\vect{w}=(\SI{20}{cm/s},0)\).
If \(r=0.4\Rightarrow \vect{w}_\text{eff}=(\SI{12}{cm/s},0)\).
With yaw \(\psi=60^\circ\), \(\unitvect{f}(\psi)=(\cos 60^\circ,\sin 60^\circ)=(0.5,0.866)\).
\[
\vect{J}_\text{wind}=\tfrac{0.08}{100}(12,0)=(0.0096,0),\quad
\vect{J}_\text{drive}=\tfrac{0.08}{100}\cdot10\,(0.5,0.866)=(0.0040,0.00693),
\]
so \(\boxed{\vect{J}_\text{sum}\approx(0.0136,\;0.00693)\ \mathrm{kg\,m/s}}\).

\subsection{Wake Blocking Reduction}
\label{sec:wake-blocking}

\paragraph{Problem we are solving.}
We need the shielding effect from an upwind blocker to fade out \emph{smoothly} with downwind distance. A hard cutoff would flicker
due to tiny motion or sensor noise, producing visible jerks. A smooth ramp avoids this.

For each upwind neighbor \(i\), compute an overlap score
\begin{equation}
  r_i = \exp\!\left(-\tfrac{1}{2}\left(\tfrac{\ell_\perp}{\sigma_\perp}\right)^2\right)
        \cdot \smoothstep\!\bigl(0, L;\, \ell_\parallel - g \bigr),
  \label{eq:ri}
\end{equation}
and take the boosted, clamped maximum
\[
  \boxed{\,r = \mathrm{clamp}\!\left(0,1,\;\gamma\cdot\max_{i\in\mathcal{N}} r_i\right)\,},\qquad
  \vect{w}_\text{eff}=(1-r)\vect{w}.
\]
Here \(\mathcal{N}\) is the set of upwind neighbors; \(\max_i\) means the \emph{maximum over neighbors}.

\paragraph{What is \(\smoothstep{}\) (and why use it)?}
\(\smoothstep(a,b;x)\) maps \(x\) from \([a,b]\) to a smooth ramp in \([0,1]\):
\[
\smoothstep(a,b;x)=
\begin{cases}
0 & x\le a,\\[2pt]
3t^2-2t^3 & a<x<b,\ \ t=\dfrac{x-a}{b-a},\\[6pt]
1 & x\ge b.
\end{cases}
\]
Its slope is zero at both ends, so blocking grows and dies out gently instead of snapping on/off.

\paragraph{Parameter meanings (visualized in Fig.~\ref{fig:blocking_geometry}).}
\begin{itemize}[itemsep=2pt]
  \item \(\ell_\parallel\): along-wind separation (downwind distance from blocker to follower, positive when follower is downwind).
  \item \(\ell_\perp\): lateral offset from the wind centerline.
  \item \(R\): blocker radius in meters (from AABB or advertised via RAB byte 0).
  \item \(\sigma_\perp = \texttt{lateral\_reach\_radii}\cdot R\): wake width (Gaussian term).
  \item \(L = \texttt{shadow\_length\_radii}\cdot R\): wake length (smoothstep interval).
  \item \(g = \texttt{upwind\_gate\_radii}\cdot R\): upwind gate distance before the ramp begins.
  \item \(\gamma=\texttt{gamma\_boost}\): optional emphasis before clamping to \([0,1]\).
\end{itemize}

  \codepath{src/controllers/air_resistance/air_resistance.cpp}:
  \codeid{ComputeEffectiveWind()}.
  \item \textbf{Wake reduction} (\eqref{eq:ri} and \(r=\min(1,\gamma\cdot\max_i r_i)\)):
  \codepath{src/controllers/air_resistance/air_resistance.cpp}:
  \codeid{IsBlockedByRAB(Real\&)} (computes \(\ell_\parallel\), \(\ell_\perp\), lateral Gaussian, smoothstep fade, boost, max, clamp).
  \item \textbf{Tunables and units} (attributes in \verb|<air_resistance .../>|):
  \codepath{src/controllers/air_resistance/air_resistance.h} (members) and
  \codepath{src/controllers/air_resistance/air_resistance.cpp} (read/validate in \codeid{Init()}).
  \item \textbf{Radius derivation (AABB)}:
  \codepath{src/controllers/air_resistance/air_resistance.cpp}:
  \codeid{EnsurePhysicsHandle()}.
\end{itemize}

\section{RAB Sensor: Role, Contract, Alternatives}
\subsection{Role}
The Range-And-Bearing (RAB) medium is used as a lightweight local-neighborhood channel. This project uses it for:
\begin{itemize}
  \item \textbf{Wake geometry:} obtain relative range/bearing to neighbors and compute upwind/lateral separations.
  \item \textbf{Scale exchange:} each robot advertises an effective radius in \textbf{RAB byte 0} (millimeters), so different robot models
  can interact without hardcoded constants.
\end{itemize}

\subsection{Contract (byte-level)}
\begin{itemize}
  \item \textbf{Byte 0 is reserved} for the advertised radius (mm), written by \codeid{CAirResistance}.
  \item Derived/user controllers may use \textbf{bytes 1..} for their own coordination messages (IDs, roles, formation state, etc.).
\end{itemize}

\subsection{Alternatives}
Alternatives depend on your simulation goals:
\begin{itemize}
  \item \textbf{Positioning sensor} could be used for global positions, but then the model depends on global knowledge (not local-only).
  \item \textbf{ARGoS proximity sensors} do not provide peer identity/range/bearing robustly for this wake geometry.
  \item \textbf{Custom medium} could encode richer state, but RAB is already standard and fast for local neighbor geometry.
\end{itemize}

function Init(node)
  // devices
  wheels   <- GetActuator("differential_steering")
  pos_sen  <- GetSensor  ("positioning")
  rab_sen  <- GetSensor  ("range_and_bearing")
  rab_act  <- GetActuator("range_and_bearing")

  // controller params
  v_desired_cm_s <- ReadParam(node, "velocity", default=5.0)

  // global config: <configuration><air_resistance .../>
  air <- GetConfigNode("configuration/air_resistance")
  angle_deg         <- ReadAttr(air, "angle_deg")
  magnitude_cm_s    <- ReadAttr(air, "magnitude")
  wind_cm_s         <- magnitude_cm_s * (cos(rad(angle_deg)), sin(rad(angle_deg)))

  // optional wake/shield tunables (defaults preserved if omitted)
  lateral_reach_radii <- ReadAttrDefault(air, "lateral_reach_radii", 3.0)
  shadow_length_radii <- ReadAttrDefault(air, "shadow_length_radii", 4.0)
  gamma_boost         <- ReadAttrDefault(air, "gamma_boost", 2.0)
  upwind_gate_radii   <- ReadAttrDefault(air, "upwind_gate_radii", 0.5)

  // optional advertised-radius sanity window (meters)
  adv_radius_min_m <- ReadAttrDefault(air, "adv_radius_min_m", 0.005)
  adv_radius_max_m <- ReadAttrDefault(air, "adv_radius_max_m", 0.20)

  // clamp obvious nonsense
  lateral_reach_radii <- max(0.1, lateral_reach_radii)
  shadow_length_radii <- max(0.1, shadow_length_radii)
  gamma_boost         <- max(1.0, gamma_boost)
  upwind_gate_radii   <- max(0.0, upwind_gate_radii)
  adv_radius_min_m    <- max(0.0001, adv_radius_min_m)
  adv_radius_max_m    <- max(adv_radius_min_m, adv_radius_max_m)
end
\end{lstlisting}

\subsection{\texttt{EnsurePhysicsHandle()}}
\begin{lstlisting}[language=pseudo]
function EnsurePhysicsHandle()
  if body_ready: return

  entity    <- GetSelfEntity()
  embodied  <- entity.GetComponent("body")

  // AABB = axis-aligned bounding box
  bb    <- embodied.GetBoundingBox()
  width <- bb.MaxCorner.x - bb.MinCorner.x
  depth <- bb.MaxCorner.y - bb.MinCorner.y
  self_radius_m <- 0.5 * max(width, depth)
  self_radius_m <- Clamp(self_radius_m, adv_radius_min_m, adv_radius_max_m)

  // cache dyn2d body pointer
  model <- GetDynamics2DModelForRobot()
  if model is SingleBody: body <- model.GetBody()
  else:                   body <- model.GetBody(index=0)
  mass_kg <- Chipmunk.GetMass(body)

  body_ready <- true
end
\end{lstlisting}

function HandleAerodynamicsPreStep()
  EnsurePhysicsHandle()

  J_sum <- (0, 0)          // reset accumulator (world frame)
  ApplyWindImpulse()       // adds (mass/100) * w_eff_cm_s

  // RAB broadcast: radius in millimeters (byte 0 reserved)
  if rab_act != null:
      r_mm <- Clamp(round(self_radius_m * 1000), 0, 255)
      rab_act.SetData(0, r_mm)
end

\subsection{\texttt{ComputeEffectiveWind()}}
\begin{lstlisting}[language=pseudo]
function ComputeEffectiveWind()
  if Norm(wind_cm_s) < 1e-9: return wind_cm_s
  r <- 0.0
  if IsBlockedByRAB(out r):
      return max(0, 1 - r) * wind_cm_s
  return wind_cm_s
end
\end{lstlisting}

\subsection{\texttt{IsBlockedByRAB(out r)}}
\begin{lstlisting}[language=pseudo]
function IsBlockedByRAB(out r)
  r <- 0.0
  if pos_sen == null or rab_sen == null: return false
  if Norm(wind_cm_s) < 1e-9:             return false

  wind_dir_hat <- Normalize(wind_cm_s)
  yaw_world    <- GetYawRadians()

  any <- false
  for msg in rab_sen.GetReadings():

      range_m <- 0.01 * msg.Range   // cm -> m
      if range_m <= 1e-6: continue

      // blocker radius from msg.Data[0] (mm->m) else fallback
      blocker_r_m <- self_radius_m
      if Size(msg.Data) >= 1:
          adv_m <- 0.001 * msg.Data[0]
          if adv_radius_min_m < adv_m and adv_m < adv_radius_max_m:
              blocker_r_m <- adv_m

      bearing_world <- yaw_world + msg.HorizontalBearing

      me_to_other <- (range_m * cos(bearing_world),
                      range_m * sin(bearing_world))
      other_to_me <- -me_to_other

      along_m <- Dot(other_to_me, wind_dir_hat)   // + means neighbor is upwind
      gate_m  <- max(1e-6, upwind_gate_radii * blocker_r_m)
      if along_m <= gate_m: continue

      lateral_vec <- other_to_me - along_m * wind_dir_hat
      lateral_m   <- Norm(lateral_vec)

      sigma <- lateral_reach_radii * blocker_r_m
      L     <- shadow_length_radii * blocker_r_m

      lateral_cov <- exp(-0.5 * (lateral_m / max(1e-6, sigma))^2)
      fade        <- smoothstep(0, L, along_m - gate_m)
      red_i       <- lateral_cov * fade

      // emphasize mid-range overlaps (optional), then clamp via max+final clamp
      red_i <- 1 - (1 - red_i) ^ gamma_boost

      r   <- max(r, red_i)
      any <- true

  r <- min(1.0, r)
  return any and (r > 1e-6)
end
\end{lstlisting}

\subsection{\texttt{DriveImpulse(v\_cm\_s)}}
\begin{lstlisting}[language=pseudo]
function DriveImpulse(v_cm_s)
  yaw <- GetYawRadians()
  fwd <- (cos(yaw), sin(yaw))              // unit forward vector (world frame)
  J_sum += (mass_kg/100.0) * v_cm_s * fwd
end
\end{lstlisting}

\subsection{\texttt{ApplyWindImpulse()}}
\begin{lstlisting}[language=pseudo]
function ApplyWindImpulse()
  w_eff_cm_s <- ComputeEffectiveWind()
  if Norm(w_eff_cm_s) < 1e-9: return
  J_sum += (mass_kg/100.0) * w_eff_cm_s
end
\end{lstlisting}

\section{Tuning and Debugging}
\subsection*{Key tunables (typical defaults)}
\begin{itemize}
  \item \(\texttt{lateral\_reach\_radii}\) widens or narrows the Gaussian cross-section.
  \item \(\texttt{shadow\_length\_radii}\) lengthens the downwind extent.
  \item \(\texttt{upwind\_gate\_radii}\) ignores near side-by-side neighbors.
  \item \(\texttt{gamma\_boost}\) emphasizes mid-range overlaps before clamping.
\end{itemize}

\subsection*{Debug tips}
\begin{itemize}
  \item Print intermediate terms inside the blocking loop: \(\ell_\parallel\), \(\ell_\perp\), \(r_i\), and final \(r\).
  \item Verify the on-screen wind arrow matches XML (\codeid{angle\_deg}, \codeid{magnitude}).
  \item If a robot seems unaffected, check advertised radius byte conversion (mm \(\rightarrow\) m), AABB-derived \(R\), and that neighbors are truly upwind (\(\ell_\parallel>0\)).
\end{itemize}
